INTRODUCTION
------------

Welcome to our Personal Accounts Suite for the Psion Series 3C/Mx and Acorn Pocket Book.

As it stands, this Shareware version is fully-working with no disabled functions, but will allow only a limited number of entries, such as 3 Accounts, 5 Standing Orders, 5 Budget Categories, 5 Shares and 5 Rooms for the Home Inventory etc.  Registration will give you more realistic values, such as 20 Accounts and 50 Standing Orders in each Group, and 50 Budget Items, 50 Shares and 20 Rooms.  Please note that registration does not involve reloading the program, but simply typing in a registration code to release the 'lock'.

ADVANCED FEATURES
-----------------

The Advanced Options Module 1 offers you the following additional functions:

    Look Ahead Mode to predict the state of your finances sometime in the future.
    Default Transactions for those regular entries.
    A ‘Last Transaction Repeat’ function
    A pull-down page of Account details where you can store such things as Account numbers.
    Automatic numbering (for cheques, or in my case registrations !)
    A ‘Find’ function in the Archive screen.

The Advanced Options Module 2 offers you the following additional functions:

    Export and Import function in various formats, including Quicken.
    A ‘Pay Bills’ option, similar to that used in MS Money. (Also needs BANKORD.OVL)
    Ability to allocate tax (VAT, GST etc) to transactions.
    Pull-down Info windows giving settings for each Group and Account.

CONFIGURATION MODULE
--------------------
The Optional Configuration Module allows you to change a large number of the settings within the program.  These settings are remembered, so you can remove this module once the program is setup to your liking.


INSTALLATION
------------

To Install the program, carry out the following actions:

1.    Copy RMRBANK.APP to your \APP\ directory.

2.    If you wish to load any of the optional modules, generate a Sub-directory \BANK\ under the \APP\ directory, i.e. \APP\BANK\

3.    You can then copy any of the optional files to the sub-directory  \APP\BANK\ if you wish to use any of the extra facilities.

4.    If you want to use the optional Print system, as well as copying the file BANKSPRT.OVL into the \APP\BANK\ Sub-directory, you will need to put the S3APRINT.DYL file into an \OPD\ directory. (Note that this latter file is common to all my programs, so if you are running more than one of them, you will only need one copy of this file)

5.    Install RMRBANK.APP using <PSION-I> as described in the Psion manual.

IMPORTANT POINTS TO NOTE
------------------------

1.    The configuration file and registration details are saved in the \OPD\ directory on your default drive, so don't be surprised if you lose that information (and registration) if you delete these files or change the default drive.  

2.    Please  do NOT try changing the name of a Group from the system screen.  The title you use for a Group is used for all the data files, not just the one shown under the icon.  If you do wish to rename a Group, simply use the 'Save As' file command from within the Program, to save the Group under a new name, change to that new Group, then use the 'Delete Group' command to get rid of the original.

3.    I have provided a BACKUP and RESTORE option (<PSION-B> and <PSION-R> in the Accounts screen) to enable you to keep a COMPLETE copy of all your data files somewhere else on the system.  Although there have only been 3 recorded cases of complete data loss in S3ABANK, I am not so arrogant as to say that there isn't a 'bug' in there waiting to trap the unwary. Personally I use this option every couple of days, as well as Backing up regularly on a PC. I think the program is safe, but I still wouldn't trust it completely.  Basically, if you lose some data and you haven't kept a backup of some description, don't expect any sympathy from me !!

4.    To register the program, press <PSION-$> and CAREFULLY enter the code obtainable from me (or my agent) for the registration fee.

5.    Important Note for Non-United Kingdom Users:    Before starting to enter data, press <PSION-C> and select your country as the Base Currency and the Group Currency.  If your country is not shown, jump forward to the 'Currency' part of Part 3 to see how to add your country.

FREQUENTLY ASKED QUESTIONS
--------------------------

Question 1.	When I update a Transaction that had 'split categories' the Budget Categories didn't update.  Why ?

Answer:  Memory limitations.  I have enough memory to store one category, so that will be updated if you update or delete the transaction.  However, I cannot spare the room to store up to 4 more categories with the split values.  Therefore, if you use 'split categories, remember it is a 'once-only' update of the categories.  Just as a reminder, the word 'Split' will appear as a reminder if you have Categories selected for the middle column.

Question 2.	I keep getting 'No System memory' reports when I have plenty available.

Answer:  In fact, the system is complaining that the program is exceeding it's maximum 128K that it is allowed.  it has nothing to do with the total system memory, as the program checks that itself before it starts.  I have tried to squeeze every last byte out of the system, but in some cases I have tried too hard.  To cure it just select 'Cache Size' in the Set Preferences menu and reduce it by 1000 bytes at a time until the problem goes away.

Question 3.	I get 'File Not Found' when I try to print using PSIWIN ?

Answer:  Try using the built-in applications.  If they don't work either you are missing a file called PSIPRINT.DYL which PSIWIN should have put into your \WDR\ directory along with PSIPRINT.WDR.  Re-run PSIPRINT Setup to see if that helps, otherwise contact Psion.

Question 4.	I can't get the Quicken Export/Import to work ?

Answer:  Here's a few pointers:

a.	The QIF file is simply a set of instructions in an ASCII text file, so it can be examined with any text editor.  So, do an Export from S3ABANK and then compare that with a QIF file from Quicken (or MSMONEY) and see if you can see any difference.

b.	If the Import command doesn't recognise your file, make sure it has a QIF extension, and if you still get the <No Files> message then press <TAB> and navigate your way to where the file is stored (normally it defaults to looking in the \BANK\ directory.)

c.	Remember you have only 100 transactions/per account before you need to archive some, so if your Quicken account has more than that then	do it in a few goes.

d.      If you want to use the Quicken Import/Export on a MAC, then when you start up the Psion Link software, from the File menu select the preferences option.  Next select the Text files preferences and add .QIF to the list of text files.  Then all files exported from S3ABank get uploaded as text files and Quicken can import them correctly. Otherwise QIF exported from S3ABANK files are assumed to be binary files and are given that attribute. 

Question 5.	Why can't I have more transactions, categories, rooms etc etc...."

Answer:  There are two factors which preclude having any more of these parameters: 

The first relates to those aspects such as Budget Categories, Rooms, and Accounts, where they are needed in a dialog to select just one.  The way the Psion dialog works limits the total length of all the descriptions to 255 characters.  Initially, I made it so there were, for example, 25 Budget Categories of a description length of 10 characters.  However, this was rather a simplistic approach, as many of the categories, such as 'Car' and 'Gas', were much less than 10 characters.  Accordingly, in later versions, I have allowed many more categories and just monitored the length of the descriptions.  If the total approaches 255 you are warned that you will have to reduce the length of some existing categories before you enter any more.

The second factor is the usual one of memory.  Unlike a PC, where the majority of the memory map is available, in the S3A, each program is limited to 64K for the program and 64K for the data.  As the program stands, I suspect I am using 63.9K for the data, as the original program will not run on a S3A until the variable names are compressed.  As such, to get the functionality that the program offers I have had to limit some of the data allocations.

This is most noticeable in the Transactions available (100/account).  Although this seems rather a small number, it should be perfectly acceptable provided you use the program as it was intended to be used and not try and use it as you would Quicken, which has unlimited storage.  The idea is that only those transactions which have not been confirmed by a written statement, and therefore may need changing, are held in the 'live' account.  Once a bank/credit card statement has arrived, all the transactions on the statement should be transferred to an archive file, which can be of unlimited size.  

The ONLY difference between the 'live' transactions and the archived transactions is that the archived transactions cannot be altered.  However, if they have been reconciled against a statement, this should not be necessary.

Therefore, for most bank/credit card accounts the 'live' account should contain only about 1-2 months worth of transactions.  Personally I find that 90 transactions is more than sufficient for this purpose.  However, if you are having trouble, there is nothing to stop you having 2 accounts to represent your single account, which would then allow you 200 transactions !!.

Hope that explains the main query I have had over the program.
