
Data-Selector help file
^^^^^^^^^^^^^^^^^^^^^^^

Compatibility
^^^^^^^^^^^^^
DatVer6a ( Series 3a version )
DatVer6c ( Series 3 classic version )

Installation
^^^^^^^^^^^^
Data-Selector should be installed on the system screen in the usual way 
by  pressing  Psion+I in the  system  screen , selecting 'DatVer6a' or 
'DatVer6c' then pressing enter ( after having copied it from the medium on 
which it is supplied into the internal disk of the Series 3 or 3a )

Using 'Data-Selector'
^^^^^^^^^^^^^^^^^^^^^
 Once installed , a list of all availiable database files should be created 
under the 'Data-Selector' icon,to start 'Data-Selector', move the highlight
onto the required file name and press enter . The start-up screen will be
displayed ( the version number and a copyright notice ) along with the 
message 'Opening file' , this will shortly be replaced with 'Loading index',
after a short delay ( the length of delay  will depend on the size of the
database being opened ) the first  record will be  shown  along with its 
position and the total number of current records ( ie 1/20 ) . 
 To move forwards or backwards through the file use the down arrow ( next ) 
or the up arrow ( previous ) ( Psion+N , Psion+P have the same effect ) to 
move to the first , Psion+F , last Psion+L .

Search , Re-search
^^^^^^^^^^^^^^^^^^  
 To perform a search press Psion+S , enter the search request in the dialog
box ( max 10 characters ) and press enter , the screen will show the number 
of records found ( if any ) and the record number being tested . If no 
records are found the index will be re-loaded . Assuming some records are 
found the first of these will be displayed . If you wish to perform a second
search on those already found , press Psion+R , If no records are found the
previous records will be re-loaded , if the re-search is successfull then 
these records become the currently valid ones . Re-searches can be performed
indefinately until the required records are found , the two types of search 
are different ( they appear the same but work in different ways ) this was 
done in order to give maximum speed , the first search should therefore
always be Psion+S as it is optimised for searching the whole file , whereas 
the re-search ( Psion+R ) goes through the file one at a time , testing only 
relevant records , this will make it slower if it has a large number of 
records to check .

Find all , Open , Exit
^^^^^^^^^^^^^^^^^^^^^^ 
 To find all records in the file , press Psion+A , to close the current file
and open a new one , press Psion+O ,to call the system screen , press 
Psion+Z , to exit , press Psion+X .

Changing views
^^^^^^^^^^^^^^
 It is possible to display the records in a simple spreadsheet type view ,
this is is activated by pressing Psion+V , the first time this is done on a
database file you will be asked to set the widths for the field displays , 
once this is done the view will change ( on the 3a version the widths must 
not exceed a total of 78 , on the Series 3 classic this is 38 , also on the
classic the characters displayed will be one less than that set in the width
dialog box , this is to force a space between fields ) If invalid widths are
set you will be unable to change views . The navigation through the records
is the same as that for the record view other than you move a page at a time
and the bottom record will move to the top ( or top to bottom ) .
 
Menu's
^^^^^^
 All key presses are displayed on the menu and can be accessed in the usual 
way .

Hints + tips
^^^^^^^^^^^^
 A mention of the width files may help aviod confusion , the width files are
stored for each database file which has been opened , in the 'OPD' directory 
using the name --ZZZZZ3.OPD , where the '--' is replaced by the first and 
last characters of the database file . IE the width file for a database 
called 'Phone' would be PEZZZZZ3.OPD ( on the version for the classic it 
would actually be PECZZZZ3.OPD having a 'C' for classic inserted , this is
only to allow me to open the same file on my machine using both versions of
the program , the width files are in different due to the screen size ) 
it should follow that if you had a database called 'Pete' it would try to 
use the same width file as 'Phone' , this can be avioded by ensuring that 
all database names start OR finish with a different letter ( re-naming 
'Pete' to 'Peter' for example ) the width files only use 56 bytes of memory
so you do not have to worry about them using up loads of memory .

Memory requirements
^^^^^^^^^^^^^^^^^^^
 Whilst the program is running it uses around 15k of memory ( 13k - 15k 
depending on where it is in the program ) it stores the table of records 
found in memory also , at any one time it is possible to have two such 
tables stored in memory , each using upto 1/20 th of the open database size
so a database of 200k in size could have two lookup tables of 10k each plus
the program size of 15k . I should say that this is a worst case as the
second lookup table is copied over the top of the first as soon as the 
Re-search is completed .
