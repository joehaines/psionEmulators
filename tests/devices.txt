# netpad: SA-1110 sibling of the netBook.  Netpad.img is a complete EPOC R5
# ROM that boots from PA 0 (the OS ROM sits at image offset 0xC0000).  The
# boot runs the board init (bit-banged I2C controller, nCS4 serial device,
# GPIO handshakes), then EPOC enters its "off" state — a real SA-1110 deep
# sleep — and the emulated power button switches it on, resuming through the
# ROM's PSPR context.  ~7 sim-seconds later the 640x240 8 bpp panel shows the
# netpad desktop (netpad logo, Documents sidebar, System toolbar, clock);
# variance settles at ~4644 with 13 unique pixel values.
netpad    | Netpad.img                      | 25 | 1000

# netbook_full: the v0.11 YModem bootloader + the actual netBook EPOC R5
# OS image attached as a CF card.  netBookLoadOsFromCard (in
# core/sa1100.cpp) does the bootloader -> OS handoff on attach: scans
# the CF for the "EPOCARM ROM" magic, strips the 256-byte header, copies
# the body to RAM bank 1 at PA 0xC8000000, disables the MMU, sets the
# boot-arg registers and jumps to 0xC8000000.  The OS then runs through
# its own cold boot.  In 93 sim-sec we see ETest.exe + WSERV reach
# their hot loops, OSMR1 ticks fire 17k+ times, and the LCD draws the
# Psion desktop with the clock ticking once a minute.
# Variance 5187, 14 unique pixel values, animation across ~3-4 frame
# hashes over the post-attach window.
netbook_full | netBook_BL_v011_eng.bin       |  3 | 5000 | --card-path roms/netbook_os.img --post-attach-seconds 90 | netbook

# netbook_eshell: the same bootloader booting the ESHELL test ROM
# (roms/ESHELL/OS.IMG) instead of the stock OS, off a synthesised FAT16
# card — the faithful medata/ATA read the browser uses by default.  Two
# things make this a regression gate rather than a curiosity: the image
# is 876 KB where the stock OS.IMG is 14 MB, so the faithful-boot
# completion gate has to scale to the image on the card; and ESHELL
# builds its own exception-vector page table, so the emulator's
# MMU-enable gap fillers must not overwrite the guest's own L1 entries.
# The console lands at "ESHELL 0.01(213) … C:\>" — two grey levels, so
# variance settles ~700 rather than the desktop's ~5000.
netbook_eshell | netBook_BL_v011_eng.bin     |  3 | 400 | --card-path tests/cards/eshell-netbook.img --post-attach-seconds 25 | netbook

# netbook_quartz: the same bootloader booting the netBook Quartz build
# (roms/OS.IMG) off a synthesised FAT16 card, the faithful medata/ATA way.
# It runs the image's own boot to the Quartz app screen — a mostly-white
# content area under a status bar carrying the clock and the free-memory
# figure — which settles at variance ~450.
#
# The window is a BAND, not a floor, because the two emulator bugs this gates
# against fail on either side of it.  Both were hard-coded netBook v1.05(450)
# addresses fired at whatever netBook OS was loaded:
#   - the UCB1200 mutex release (VA 0x8000001C) landed on entry 5 of this
#     kernel's interrupt-name table, truncating Interrupt::IdFromName() until
#     the PC-Card driver faulted into the debug monitor — blank panel,
#     variance 0, caught by the floor;
#   - the PC-Card caps-handler hook (PC 0x5001cc54) forced r3=0 in the middle
#     of this build's locale collation loop, an unhandled data abort a fifth
#     of a second after the splash — the machine parks on the SPLASH, variance
#     ~11200, which a floor alone waves through.  The ceiling catches it.
# See docs/netbook-quartz.md.
netbook_quartz | netBook_BL_v011_eng.bin     |  3 | 200 | --card-path tests/cards/quartz-netbook.img --post-attach-seconds 60 --max-variance 2000 | netbook
